# Deviations & deferred work

`ENGINEERING_STANDARDS.md` is binding ("Jedes Repo wird daran gemessen"). A repo
that silently ignores binding rules has no standards — so every deviation is
recorded here, dated, with a disposition. Same for remediations the wart
catalogue promises but no stage owns. Hostile review (worklog session 7) forced
this file into existence; that is working as intended.

Status values: **deferred(stage)** = lands in a named stage · **deferred(post-v1.0)**
= explicitly outside this project's scope, would need owner re-scoping ·
**waived** = will not be done in this repo, reason given.

| Security-Scan in CI | **met** (2026-08-05, G7) — image scanning is **reporting-only**, stated not hidden | Since 2026-07-30: Dependabot (modern/e2e/characterization + actions; since 2026-07-31 also **npm for `modern/frontend`** — stage 5 had opened the ecosystem without scanning it, caught by review session 10; `legacy/` **excluded on purpose** — its EOL dependencies are the exhibit). 2026-08-05: **Trivy** scans the built modern image in `modern-ci` for CRITICAL/HIGH in OS packages and Java dependencies — the layer Dependabot structurally cannot see, because a CVE in the JRE base image appears in no manifest and ships anyway. Two limits belong next to that: it runs with `exit-code: 0` (**reporting, not blocking** — a fresh CRITICAL in a base image arrives without any commit of ours, and a gate that reddens master overnight for something nobody caused is a gate people learn to bypass), and a separate OWASP dependency-check was **not** added, because it would duplicate what Dependabot and Trivy already cover and now needs an NVD API key to run at usable speed. **It paid for itself on the first CI run:** one HIGH finding, **CVE-2026-54291** in `org.postgresql:postgresql` 42.7.11 — a man-in-the-middle protection bypass via a SCRAM-SHA-256-PLUS downgrade, i.e. precisely the authentication mechanism PostgreSQL 18 uses, which stage 6 had just switched the modern stand to. Fixed the same day by pinning 42.7.12 (the minimum fixed version, not the newest — this is a security fix, not a version bump). Fixing it exposed a second, quieter hole: the G6 testbed and `modern/pom.xml` both left the driver version to Boot's dependency management, and a property override travels through Boot's `<parent>` but **not** through the testbed's imported BOM — so `PomDriftGuardTest` stayed green while the two classpaths silently disagreed. Both now declare the version literally, which is what makes the guard able to see it. |
| AuthN/AuthZ (OAuth2/OIDC, Keycloak) — §4 | **G7's hard requirement met** (2026-08-05) at the edge · full OIDC still **owner re-scoping needed** | The 2016 app has no auth at all; adding it changes every pinned contract, so it cannot happen as a side effect (ADR-0004 gate). Recorded honestly instead of silently (review session 10): the modern stand — including the destructive `POST /admin/bereinigen` the JSP wart B16 bequeathed — is unauthenticated by inherited design. The G7 requirement was *"protect `/admin` at minimum (reverse-proxy auth counts)"*, and that is exactly what shipped: Basic auth in a Traefik overlay covering `/admin`, `/api/admin` and `/actuator` ([ADR-0014](adr/0014-authentifizierung-am-edge.md)), measured 401 without credentials and 200 with them, wrong password 401. **What that is not:** the application itself is still unauthenticated, so anyone who can reach its port bypasses the lock — which is why a real host must not publish it (`deployment.md` §12). The measured price of doing it in the application instead: a matcher scoped to `/admin` alone turns 4 safety-net tests red, each one an ADR-0004 sanctioned-divergence decision. Full OAuth2/OIDC per §4 remains an owner-scoped stage of its own plus the §9 auth ADR. |
| Security-Header, Rate Limiting — §4 | **met at the edge** (2026-08-05, G7) for the modern stand · never for `legacy/` | Delivered by the Traefik overlay ([ADR-0014](adr/0014-authentifizierung-am-edge.md)), verified by `modern/edge/verify-edge.sh`, not asserted: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, a CSP whose `script-src` is strict, and a token-bucket rate limit measured firing (200 concurrent requests → 103–173 × 429 across five runs; the same burst straight at the application → 0). HSTS ships **off** (`stsSeconds: 0`) on purpose: enabled over plain HTTP it teaches the browser to refuse `http://localhost` for a year; the TLS-terminating host sets it. `legacy/` gets none of this — it is the exhibit. |
| CSRF-Schutz — §4 | **deliberately not implemented**, reason recorded | Not an oversight and not deferred-by-drift: the application has no session, no cookie and no ambient authority, so a classic CSRF token would protect nothing. That residual risk is written down in `SECURITY.md` and accepted for a demonstration stand; the real fix (session-based OIDC plus token) belongs to the owner-scoped auth stage below, not to an ops stage. Enabling Spring Security's CSRF today has a measured price: 17 characterization write calls plus every E2E write scenario turn red, i.e. it is a pinned-contract change under the ADR-0004 gate. |
| CSP without `'unsafe-inline'` for styles — §4 | **new**, deferred(post-v1.0), owner scoping needed | The shipped policy is strict everywhere except `style-src`, which carries `'unsafe-inline'` because Angular injects component styles as `<style>` elements at runtime (measured 2026-08-05: with `style-src 'self'` the browser blocked them). | P2 PostgreSQL 9.6 (EOL) | **met for the modern stand** (2026-08-05, G7) · legacy stays 9.6 permanently, by design | The modern stand runs **PostgreSQL 18** with `en_US.utf8` pinned explicitly ([ADR-0012](adr/0012-postgresql-18-und-fixierte-collation.md)); the equivalence gate survived it (47/47 both stands, and `/api/bericht/topkunden` byte-identical across the version boundary, decimal literals included). The upgrade produced the two findings that make it worth reading: `postgres:18-alpine` **reports `datcollate=en_US.utf8` and sorts in C order**, and the image moved `PGDATA` and its declared `VOLUME`, so a naive tag bump silently stops persisting data while every health check stays green. `legacy/` keeps 9.6 for ever — an EOL database is part of what the exhibit demonstrates — which means the two stands now run different majors **on purpose**, and that is what gives the equivalence gate something to prove. |
| B20 `static final SimpleDateFormat` in `WerkstattService` (**newly found**) | **new** (2026-08-05, G7), deferred(post-v1.0) | Found by the static analysis armed in this stage, on its first run: `WerkstattService:37` holds one `SimpleDateFormat` for all threads, under a 2016 comment that says so out loud — *"eine Instanz fuer alle Threads, hat bis jetzt eh immer funktioniert"*. `SimpleDateFormat`'s own Javadoc states it is not synchronised; the field is used by `/api/admin/statistik`, which a monitor will now poll. **Not fixed here, on purpose:** the ops stage's job is the deployment surface, not editing the God class that is G6's study object, and this repository's rule is that found items are ledgered for an owner decision rather than quietly absorbed. Cheap when it is scheduled — `DateTimeFormatter` produces the identical string for `dd.MM.yyyy`, and the characterization suite pins that endpoint, so the safety net can prove the fix behaviour-preserving. **We did not reproduce a corrupted response under load and do not claim to have.** |
